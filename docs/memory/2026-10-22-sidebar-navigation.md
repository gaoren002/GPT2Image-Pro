# 2026-10-22 侧栏切页修复

- 现象：点侧栏 tab 有时不会立即切换；没反应时再点另一个 tab，问题尤其明显。
- 根因（`585f61e` 之前）：
  - 侧栏 `Link` 全部 `prefetch={false}`，每次点击都要等服务器往返，旧页面才会换掉。
  - 点击拦截：导航挂起时执行 `window.stop()` + `location.assign()` 整页跳转。`stop` 会掐断进行中的 RSC 请求，而 Next 对失败的导航兜底是整页跳回其原目标，结果覆盖了新点击的目标。限速（600ms / 60KB/s）实测：先点全局状态再点历史记录，60 秒未到达历史记录、整页加载 2 次、最终停在全局状态。拦截的前提“App Router 不能取消进行中的导航”在 Next 16 不成立：`app-router-instance` 的 `dispatchAction` 会把挂起的导航标记为丢弃，并立即开始新导航。
- 修复（`585f61e`、`e562bd7`）：去掉拦截，完全交给 `Link` 软导航；恢复默认预取（只取到 `loading.tsx` 骨架）；`useLinkStatus` 在被点击项上画脉动竖线。效果：URL 与骨架在 0.03-0.05s 内切换（原 0.7-1.06s），连点 0.15s 到达且无整页重载。
- **不变量**：每个 dashboard 路由都必须保留 `loading.tsx`。默认预取对动态路由只渲染到最近的 loading 边界，不执行 `page.tsx`（已用预取响应内容和 `pg_stat_statements` 的查询计数两种方式验证）。一旦缺了 loading 边界，预取就会执行整个页面；而公告页（渲染时标记已读）、工单详情页（更新 lastSeenAt）都有渲染期写入，会被预取误触发。
- 未读角标：侧栏在共享布局里，软导航不会重渲染。“打开即已读”的页面渲染 `SidebarUnreadSync`，挂载后派发事件让侧栏立即刷新；切页触发的刷新延迟 3 秒，并且至多每分钟一次（避免与切页请求争抢带宽）。修复了 24408b4 引入的“读完红点要整页刷新才消失”。
- 已知取舍：首次进入某页时，内容完整出现比旧版晚约 0.35s（先提交预取骨架、再延迟揭示内容，属于 React / Next 的调度机制）；再次进入则更快（0.81s，旧版 1.31s）。
